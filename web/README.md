# Classy Web

기존 Classy Django API를 이용하는 독립 React 웹 프론트입니다. Flutter 소스는 유지합니다.
백엔드 변경은 판매 중인 강의 목록의 비로그인 조회 허용으로 한정하며, 영상 재생·대여·등록 권한은 유지합니다.

2026-09-29 리디자인: 실제 앱의 색상·타입·SVG·화면 구성을 바탕으로 웹 레이아웃을 재구성했습니다.
화면별 기준은 [DESIGN.md](DESIGN.md), AWS 및 DNS 연결 상태는 [DEPLOYMENT.md](DEPLOYMENT.md)를 참고하세요.

## 실행

Node.js 22.12+ 또는 24에서:

```sh
npm ci
npm run build
npm start
```

http://127.0.0.1:4173 에 접속합니다. 개발 시에는 `npm run dev`를 사용합니다. 두 서버를 같은 포트에서 동시에 실행하지 마세요.

서버 실행 환경변수 `CLASSY_API_URL`, `HOST`, `PORT`로 설정합니다. `.env.example`은 참고용이며 파일이 자동 로드되지는 않습니다. 기본 API는 `https://api.classystudy.com`, 기본 호스트는 로컬 컴퓨터입니다.

브라우저의 `/api/*`를 고정된 API 서버로 전달하는 프록시가 있어 Django의 CORS 설정 변경이 필요 없습니다. 정적 파일만 업로드하면 프록시가 사라지므로 Node 서버나 동등한 reverse proxy가 필요합니다. 운영 사이트는 https://classystudy.com 이며 AWS Nginx가 API를 프록시합니다.

## 연결한 기능

- 학생·강사 회원가입, SMS 인증, 비밀번호 찾기·재설정
- 이메일/비밀번호 로그인, 다중 역할 계정 전환·추가, 로그아웃·회원 탈퇴
- 선생님·학생 공고 탐색, 검색, 과목 필터, 상세와 후기
- 학생 모집글·강사 과외 소개 작성/수정/삭제, 모집 마감·재개, 지역 및 과목 선택
- 학생 상담 제안, 강사 역제안, 채팅방 과외 성사 등록·증빙 제출·입금 안내
- 성사 수업 목록, 후기 작성·수정·삭제
- 강의 검색(`q`), 상세, 찜, 댓글, 무료 미리보기, 수강 권한에 따른 영상 재생
- 기존 캐시로 강의 대여: 금액을 보여준 뒤 명시적 확정
- 학생의 대여·만료·찜 강의와 찜한 선생님 목록
- 강사 스튜디오: 업로드 진행률, 영상 미리보기, 현재 장면 썸네일 생성, 계정별 로컬 초안 자동 저장, 게시 체크리스트
- 강의 제목·소개·가격 수정, 판매 중지·재개·삭제, 실제 조회수 집계
- 캐시 내역·쿠폰, 구매별 환불 조건과 결제처 웹 환불 경로 안내
- 강사 인증 서류 제출·재제출, 수익 조회·계좌 등록·정산 신청
- 채팅 텍스트·이미지 전송, 읽음 처리·즐겨찾기·음소거·나가기·차단; 열린 대화는 5초 간격 갱신
- 댓글·답글 작성과 본인 댓글 수정·삭제, 맥락별 신고·차단 관리·1:1 문의
- 알림 조회·전체 읽음·삭제, 프로필 사진·휴대전화 변경
- PC·모바일 반응형 화면, 로딩·빈 결과·오류 상태

## 현재 범위 및 검증 경계

**남은 의존성: 웹 캐시 충전.** 기존 결제 API는 Apple/Google 영수증만 검증합니다. 웹 PG 계약·운영 키가 제공되지 않아 웹 결제나 캐시 지급을 임의로 구현하지 않았습니다. PG 선택 후 서버 측 결제 검증, 중복 지급 방지, 환불·웹훅·원장 연동을 추가해야 합니다. 기존 스토어 구매는 결제처 웹사이트의 환불 요청 경로로 안내합니다.

브라우저가 닫힌 상태의 웹 푸시는 미연동입니다. 서비스 내 알림과 대화 조회는 사용 가능하며 실시간 대화 수신은 폴링 방식입니다.
대용량 업로드의 파일 자체는 브라우저 종료 후 복원하거나 중단 지점부터 재개하지 않습니다. 텍스트·설정만 계정별 로컬 초안으로 저장합니다. 시간 초과 시 서버에 이미 반영됐을 수 있어 자동 재전송하지 않습니다.

운영 DB와 기존 학생 권한으로 읽기 전용 진단을 실행해 강의 2개가 조회되는 것을 확인했습니다. 실제 결제, 문자 발송, 메시지 전송, 계정 생성, 강의 업로드는 운영 환경에서 실행하지 않았습니다.

인증 이후 핵심 흐름은 Playwright의 모의 API 응답으로 검증하며, 운영 계정 검증을 대신하지 않습니다. 비밀번호는 저장하지 않고 토큰은 현재 브라우저 탭의 sessionStorage에 저장합니다. 서버에 키를 복사하거나 코드에 자격증명을 넣지 않았습니다.

## 검증 명령

```sh
npm test
npm run build
npx playwright install chromium
# 실행 중인 웹 서버가 필요합니다.
node tests/browser.mjs
node tests/authenticated.mjs
node tests/web-features.mjs
node tests/service-workflows.mjs
CLASSY_TEST_ORIGIN=https://classystudy.com node tests/aws-smoke.mjs
```

기존 Chromium 실행 파일을 사용하려면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`을 지정합니다. 테스트는 로그인/결제/전송 응답을 가로채므로 실제 사용자의 데이터에 쓰기 작업을 하지 않습니다.
